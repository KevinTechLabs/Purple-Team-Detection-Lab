# Gap: T1070.003 — Clear bash history (missed)

## What was tested
Atomic Red Team T1070.003 clears command history. The variant that ran used a
shell builtin (`history -c` / unsetting `HISTFILE`), which clears the in-memory
history and never writes to the `.bash_history` file on disk.

## Why the auditd watch missed it
The rule watches the file:
```
-w /root/.bash_history -p wa -k T1070_history
```
A builtin that never touches the file produces no file-write syscall, so there is
nothing for auditd to record. The watch is correct for the `rm`/truncate variants
of the technique but blind to the builtin.

## Fix (planned)
History tampering via builtins is genuinely hard to catch with file auditing.
Options, roughly in order of reliability:

1. **Shell-level auditing** — ship a `PROMPT_COMMAND`/`session` audit that logs
   every command to syslog (e.g. `pam_tty_audit`, or auditd `execve` logging of
   all commands) so `history -c` itself is recorded as a command.
2. **Detect the absence** — alert when a session ends with a suspiciously empty
   or truncated history relative to the commands auditd saw run.
3. **Immutable history** — `chattr +a ~/.bash_history` so truncation attempts
   fail and generate an error worth alerting on.

Option 1 is the cleanest and would also strengthen the discovery detections, so
it's the tracked next step.
